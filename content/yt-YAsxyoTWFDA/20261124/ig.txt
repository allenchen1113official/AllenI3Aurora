用 Claude Code 1000 小時的功能排行：3 個 S 級，為什麼 /init 只拿 C
艾倫極光報報 ALLEN I³ AURORA BRIEF｜常看 YouTube 重點筆記 2026/11/24（週二）

▶ The Coding Sloth〈I Have Spent 1000+ Hours With Claude Code. This Is What I Learned〉（2026-08-18・22 分 30 秒）

📌 重點摘要
• 作者用 20 美元方案，最大痛點是用量限制，因此把常用功能做 S～F 分級，並分享省 token 的方法。
• S 級三件事：技能 skills（到 skills.sh 找，別一次裝一堆）、plan mode（大任務才用）、驗證（先寫測試再實作、跑型別檢查與 linter、截圖或瀏覽器測試）。
• /init 只拿 C～D，但 CLAUDE.md 值得寫：專案說明、現況、程式風格；MCP 只在需要和外部系統互動時才裝。
• Context 管理：一個任務一個新對話、別讓它亂查、提示要非常具體；超過約 10～20 萬 token 品質就下滑，自動壓縮出現就該重開。
• 其他：/loop 做定時自動化、子代理與 worktree 平行開發；替代品有 Codex、OpenCode、Cursor、Copilot；最後提醒還是要學會寫程式。

📝 康乃爾筆記
🔹 S 級：技能、plan mode、驗證；驗證是工程基本功，AI 只是讓它更重要
🔹 驗證順序：先寫測試再實作，否則 AI 只會寫出能通過自己程式碼的測試
🔹 省 token：一任務一對話、限制亂查、提示具體、自己下 /compact 並指定要保留什麼
🔹 自動化：/loop 像 AI 版排程：每天挑 issue 開 PR、掃漏洞、發想功能
🔹 心態：會寫程式才看得懂 AI 在做什麼，用量用完也還能繼續前進

💡 一句話總結：功能不必全學，把技能、計畫、驗證做好，再省著用 context 就夠了。
